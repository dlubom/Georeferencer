## Kontrakt i zmiany testów

Domyślny CLI zapisuje osobny kompletny przebieg do `build/geotiff`.
`--all`/`--changed` tworzą pełny aktualny katalog, bez mtime; `--cave`
pozostaje podzbiorem. Cache używa fingerprintów treści/kodu/środowiska,
ale zawsze przechodzi preflight i rzeczywisty odbiór GeoTIFF. Wymuszenie,
naprawa cache i zmiany zakresu są badane na syntetycznych źródłach.

Wycofano zapis computed/TFW do źródeł. Dotychczasowe smoke i testy modeli
sprawdzają teraz jawne i domyślne osobne wyjście. Porównanie T04 z dawnym
zapisem działa tylko na kopii danych w /tmp, z zamrożonym generatorem T06
sprawdzonym **oryginalnym hashem** raportu T06. Testy awarii wymagające
uruchomienia GDAL używają `force=True`, aby cache nie ominął kontrolowanego
miejsca awarii. Nie usunięto żadnej kontroli liczb, obrazu, modelu ani historii.

ZIP zawiera dokładny przebieg: manifest i trzy pliki na plan, zamiast
dawnego płaskiego globu TIFF. Dzięki temu bramka nie pomija braków i zachowuje
proweniencję. Oba zdarzenia wydania wywołują tę samą funkcję pełnego T09.
Wyjątki QA nie zostały zmienione. Testy workflow sprawdzają wspólną bramkę
przed publikacją i nowy runtime zamiast starych poleceń apt/zip/copy.

Kontrola zaczyna się od testów `tests/host/` (prawdziwy Git, biblioteka
standardowa i wrapper). GDAL, obliczenia, historia oraz QA pozostają w tym
samym przypiętym kontenerze co wcześniej. Obraz nie zawiera Git; hostowe
testy odpowiadają rzeczywistemu miejscu wykonywania selekcji.

## Odtworzenie

```sh
./scripts/check
./scripts/build generate --all
./scripts/build generate --changed
./scripts/build package --mode tag --run-dir /build/geotiff/current \
  --reports-dir /build/tag-qa --archive /build/tag-dry-run.zip
./scripts/build package --mode manual --run-dir /build/geotiff/current \
  --reports-dir /build/manual-qa --archive /build/manual-dry-run.zip
git status --short
```

Te komendy tworzą wyłącznie lokalne wyniki, raporty i ZIP. Nie uruchamiają
GitHub Release. Końcowa rewizja PR ma linki CI w opisie PR.
Poniżej zapisano odbiór aktualnej wersji kodu; ostatni commit uzupełnia dokumentację.

Audyt parametrów i niezmienności danych można odtworzyć osobno:

```sh
mkdir -p build
git show 16f5cb2f3ea101b2552f9536673146c4ed8a6b74:pipeline/02_generate_geotiff.py > build/t09-generator.py
git diff 16f5cb2f3ea101b2552f9536673146c4ed8a6b74 --name-only -- data parquet 'docs/reports/t0[5-9]*' > build/t10-protected-changes.txt
docker build --platform linux/amd64 --iidfile build/audit-image ci
docker run --rm --platform linux/amd64 --network none \
  --mount "type=bind,source=$PWD,target=/workspace,readonly" \
  --mount "type=bind,source=$PWD/build,target=/build" \
  "$(cat build/audit-image)" python docs/reports/t10-build-impact.py \
  --before /build/t09-generator.py --protected-changes /build/t10-protected-changes.txt \
  --output /build/t10-impact-audit.json
```

parametrów można porównać z odtworzonym JSON-em.
